一句話結論

佩欣目前不是單純在「填表」或「提醒人」，而是在多個系統之間扮演人工流程中樞：接收表單、檢查資料完整性、轉貼 Line、開行事曆、追課綱與講師資料、核對金額、整理流水帳、通知未完成者、更新 Info、改檔名、維護 Excel 總表。

她現在的工作流程與優化可能

這段接在痛點說明後面，讓讀者先看懂佩欣現在怎麼做，再判斷哪些地方最值得先優化。

1課務 / 客戶申請

目前流程

單位填 Google 表單後，佩欣檢查欄位完整性；完整就整理成固定格式貼到 Line 群組，等 Abby 或淑菁派講師；講師確認後建立 Calendar，再追講師資料、課綱、簡報與單位需求。

優化可能

建立新申請、缺漏、待派課、待開行事曆與課綱/簡報 due list，並產生 Line 草稿。

2單據核銷

目前流程

填表後，佩欣依星展、中信培力、信扶專案、公司課程與辦公室分類；核對公里數、費率、金額與單據；星展另 key 流水帳與扣繳資料，月底/月初再提醒與逐人回覆。

優化可能

做核銷檢查器，依專案套費率、標出疑似錯誤與缺件，產生逐人通知草稿。

3庫存管理

目前流程

佩欣維護 Excel，記錄教材/道具數量、借出日期、活動、借出單位、歸還或未歸還狀態。

優化可能

先產生借出、歸還、低庫存、未歸還清單，不急著改原 Excel。

4季刊訂閱

目前流程

訂閱者透過 QR Code 或 Google 表單登記紙本/電子版；佩欣把資料搬到總表；電子版寄連結，紙本整理地址、續訂、退件與地址異動。

優化可能

自動分類電子/紙本，電子版先產生 Email 草稿，地址異動做重複資料比對。

5分區會議

目前流程

引導員到 Excel 登記時段；會前一天佩欣提醒並給會議連結；會後整理逐字稿、校正名字與狀態，再檢查 Info 欄位，未更新就截圖通知。

優化可能

建立會議包：會前提醒、逐字稿校名單、進度表比對、未更新清單與提醒草稿。

6財務諮詢紀錄

目前流程

諮詢師約訪並填諮詢記錄；Info/評論與欄位常不同步，佩欣要檢查缺漏、駁回原因與補件狀態；都完成後才勾諮詢完成，作為發薪依據。

優化可能

補件追蹤清單列出諮詢師、案子、缺欄位、拖延天數與提醒草稿；完成勾選仍人工確認。

7小老闆日誌 / 郵寄

目前流程

有人填表申請寄送手冊或小老闆資料後，佩欣寄出並在 Google 表單或 Info 補完成狀態與寄送日期。

優化可能

列出待寄送、待回填日期、待勾完成清單，低風險狀態欄再評估半自動寫回。

8粉絲團文章

目前流程

佩欣每天把粉絲團文章存到 Info，建立事件、評論並送審，主要作為紀錄與行政依據。

優化可能

建立貼文收件清單與 Info 建檔 checklist，欄位固定後產生貼文摘要與待填草稿。

9個案轉介與家系圖

目前流程

社工或單位填轉介表單並進 Line；佩欣核對資料、安排電訪行事曆、回填 Line 進入時間與電訪時間；家系圖依固定格式改名並存入資料夾。

優化可能

先做資料完整性與檔名建議，不自動寫回個案資料；Calendar 可做需確認的草稿。

三層自動化能力

每日工作台

讀取各表單與 Excel，整理新申請、缺漏、今日到期、已逾期、需要問人的事項。

草稿產生器

產生 Line、Email、Calendar、核銷說明、補件提醒、會議紀錄與檔名建議。

受控寫回

經佩欣確認後才寫回 Sheet、建立 Calendar、寄送信件、操作 Info 或更新狀態欄。

安全邊界：涉及個案、戶籍、財務諮詢、薪資依據、Info 送審與外部發送的動作，不建議無人確認全自動化。

Codex 自動化任務規劃

Phase 0
資料盤點

先看欄位結構，不處理真實外部動作

  • 取得課務、教材、核銷表單的檢視權限。
  • 建立資料字典：欄位、狀態、日期、個資欄位。
  • 整理 Line、Email、核銷、補件與會議提醒模板。
Phase 1
每日工作台

每天自動整理「今天要看什麼」

  • 課務新申請、缺漏、待派講師、待開 Calendar。
  • 核銷待核對、缺公里數、金額可能錯誤。
  • 財務諮詢缺欄位、被駁回、逾期未修正。
Phase 2
草稿產生

降低複製貼上與重寫訊息的時間

  • 課務申請轉 Line 群組固定格式。
  • 核銷逐人金額說明草稿。
  • 課綱、簡報、財務諮詢補件與會議提醒草稿。
Phase 3
受控寫回

草稿穩定後，把低風險動作半自動化

  • 建立 Calendar 事件或更新 Sheet 狀態欄。
  • 季刊電子版寄送與檔案改名，需先確認。
  • Info、Line、發薪相關狀態維持人工確認。

建議優先做的三個小實驗

A. 課務每日追蹤工作台

只接課務 Google Sheet 與教材表單，產出新申請、缺欄位、待派講師、待開 Calendar、課綱與講師資料 due list。

  • 效益：每天都用，最容易驗證省時。
  • 風險：需要實際欄位與課綱模板。

B. 核銷金額檢查與通知草稿

讀取核銷表單匯出資料，依星展、中信培力、信扶專案、公司課程、辦公室分類，檢查公里數、費率與總金額。

  • 效益：重複度高，錯誤成本明確。
  • 風險：費率與進位規則要先定稿。

C. 財務諮詢補件追蹤

每天列出哪位諮詢師、哪個案子、缺哪個欄位、拖了幾天、建議提醒文字；先不寫回 Info。

  • 效益：直接改善補件拖延。
  • 風險：個資敏感，需遮罩與最小權限。

可能的解決方案

方案 最適合 優點 限制
Google Sheets + Apps Script 課務、教材、季刊、核銷、Calendar、Gmail 貼近既有 Google 表單工作流，成本低，上手快。 Info、Line、複雜檔案處理不一定能完整處理。
Codex 本地半自動工作台 Excel 檢查、草稿、會議紀錄、檔名整理、核銷檢查 適合先做草稿與報告，不必一開始新建系統。 每天自動跑需要後續排程與權限設計。
佩欣工作台 Web 小工具 長期整合九大工作流 流程狀態清楚，能降低遺漏與追蹤成本。 開發量較大，需要登入、權限、個資遮罩與稽核紀錄。
Info 瀏覽器 / RPA 輔助 Info 無 API 但需要每天查欄位、建事件、送審、截圖 能處理現有系統限制。 畫面變動風險高，個案與發薪狀態必須保留人工確認。

推薦導入節奏

第 1 週

欄位盤點、模板整理、課務每日工作台原型。

第 2 週

核銷檢查與訊息草稿，修正課務工作台。

第 3 週

財務諮詢補件追蹤，季刊電子名單整理。

第 4 週

分區會議紀錄與未更新提醒，評估寫回與發送權限。

待確認問題

  1. 課務表單、教材表單、核銷表單的欄位名稱與實際狀態欄有哪些？
  2. 各專案交通費費率與進位規則是否固定？星展汽車/機車、中信 5.5 元規則要確認。
  3. 課綱、講師資料、簡報的標準 due date 是固定規則，還是依單位需求不同？
  4. Line 通知目前能否接受「草稿由佩欣貼上」，還是未來希望系統發送？
  5. Info 是否有匯出、API、批次匯入或只能人工操作？
  6. 財務諮詢與個案轉介資料中，哪些欄位可讓 Codex 讀？哪些需要遮罩？
  7. 季刊電子版是否有固定連結、固定寄送信件模板、退訂機制？
  8. 家系圖命名格式的完整規則是什麼？

發布與治理邊界

  • 所有外部發送先採草稿模式。
  • 涉及個案、戶籍、家系圖、財務諮詢紀錄，先做遮罩與最小權限。
  • 涉及薪資、諮詢完成、Info 送審，不做無人確認的全自動點擊。
  • 每次自動化輸出都保留來源列號、產生時間、操作人與是否已人工確認。
  • 先讓自動化跑 1-2 週，確認沒有漏報、誤報、噪音過多，再考慮寫回或發送。

建議第一個交付版本

先做「課務 + 核銷」雙工作台：每日新申請、缺漏欄位、派課狀態、Calendar 狀態、課綱/簡報/講師資料 due list、依專案分類的核銷檢查、缺件清單與逐人通知草稿。
